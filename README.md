# playwright-ts-template

Playwright + TypeScript starter for end-to-end test automation, with AI agent skills for Claude Code, Cursor, GitHub Copilot and Codex generated by [wico-playwright-agent-skills](https://github.com/willcoliveira/qualiow-playwright-skills) (`wico` is the npm package name; the repository is `qualiow-playwright-skills`) and by Playwright itself.

## What you get

- Playwright 1.63 with a config that loads `.env`, uses sensible timeouts, retries and traces on CI, and produces one merged HTML report from sharded runs.
- Page Object Model example (`src/pages/home.page.ts`) and an example spec that runs against `https://playwright.dev`.
- ESLint 10 (`typescript-eslint`, `eslint-plugin-playwright`), Prettier, `tsc --noEmit`.
- GitHub Actions: a lint job, a two-shard test matrix and a merge job publishing the HTML report.
- Dockerfile on the official Playwright image (tag kept equal to the installed `@playwright/test` version by CI).
- Four agent skills, regenerated by one command and checked for drift in CI:
  - `playwright-e2e` — how to plan, write, debug and review tests **in this project** (wico).
  - `playwright-cli`, `playwright-trace`, `playwright-component-testing` — Playwright's official skills.

The tests target `https://playwright.dev` as a demo; point them at your application with `BASE_URL`.

## Requirements

- **Node.js ≥ 22.13** (`.nvmrc` pins 22.20; `nvm use` picks it up).
- **Docker** only if you want to run the suite in a container.
- Recommended: the [Playwright Test for VS Code](https://marketplace.visualstudio.com/items?itemName=ms-playwright.playwright) extension (test explorer, trace viewer, locator picker).

## Getting started

Click **Use this template** on GitHub (or clone the repository), then:

```bash
nvm use
npm ci                 # dependencies only — no browser download on install
npm run pw:setup       # installs the Playwright browsers (+ OS deps on Linux)
cp .env.example .env   # optional: BASE_URL for your application
npm test
```

Or, with the Makefile: `make install && make test`.

## Running tests

| Command                             | What it does                                           |
| ----------------------------------- | ------------------------------------------------------ |
| `npm test`                          | All projects (chromium, firefox, webkit), headless     |
| `npm run test:chromium`             | Chromium only                                          |
| `npm run test:headed`               | Visible browser                                        |
| `npm run test:ui`                   | Playwright UI mode                                     |
| `npm run test:debug`                | Playwright inspector                                   |
| `npx playwright test --grep @smoke` | Only tests tagged `@smoke`                             |
| `npm run report`                    | Open the last local HTML report                        |
| `npm run report:merge`              | Merge blob reports from `./all-blob-reports` into HTML |

Every npm script has a `make` equivalent (`make help` lists them).

### Debugging with an AI agent

`npx playwright test --debug=cli` pauses the test and prints a `playwright-cli attach …` command; the `playwright-cli` and `playwright-trace` skills teach the agent that loop, and `.claude/skills/playwright-e2e/references/agent-debugging.md` describes the workflow used in this project.

## Docker

```bash
make docker-build   # docker build -t playwright-ts-template .
make docker-test    # runs the suite inside the image (--init --ipc=host) and copies the HTML report to ./playwright-report
```

The image is `mcr.microsoft.com/playwright:v<version>-noble`, where the version is the installed `@playwright/test`; the CI lint job fails when the two disagree. Tests run as the image's unprivileged `pwuser`.

## CI

`.github/workflows/tests.yml` runs on pushes and pull requests to `main`:

1. **lint** — `eslint`, `tsc --noEmit`, `prettier --check`, `npm run skills:check` (generated skills must be in sync) and the Dockerfile tag check. No browsers are installed here.
2. **test** — a two-shard matrix (`--shard=N/2`), each uploading a blob report. Set a repository variable `BASE_URL` to test your application instead of the demo target.
3. **merge-reports** — downloads the blobs and publishes a single `playwright-report` artifact (7 days).

## Environment variables

`playwright.config.ts` loads a local `.env` (Node's `process.loadEnvFile()`); CI passes variables directly.

| Variable   | Description                                                         | Default                  |
| ---------- | ------------------------------------------------------------------- | ------------------------ |
| `BASE_URL` | Application base URL used by `page.goto('/')`                       | `https://playwright.dev` |
| `CI`       | Set by CI: enables retries, forbids `test.only`, switches reporters | –                        |

## AI agent skills

```bash
npm run skills:sync    # regenerate everything below
npm run skills:check   # what CI runs: sync, then fail if anything changed
```

| Path                                                                                                                         | Owner                                                                                            | Purpose                                                                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.claude/skills/playwright-e2e/`, `.agents/skills/playwright-e2e/`                                                           | `wico-playwright-agent-skills` (`init --platforms claude,cursor,copilot --packs core,templates`) | Test planning, generation, debugging, review; page-object and project conventions; fixtures/auth, locators/assertions, CI and flake triage, API testing, pass-rate analysis |
| `.cursor/rules/playwright-e2e.mdc`, `.github/instructions/playwright-e2e.instructions.md`, `.github/copilot-instructions.md` | wico                                                                                             | Cursor and Copilot pointers to the shared skill                                                                                                                             |
| `.claude/skills/playwright-cli/`, `.agents/skills/playwright-cli/`                                                           | `npx playwright init-skills`                                                                     | Driving a browser and debugging tests with `playwright-cli`                                                                                                                 |
| `.claude/skills/playwright-trace/`, `.agents/skills/playwright-trace/`                                                       | `npx playwright init-skills`                                                                     | Analysing traces with `npx playwright trace`                                                                                                                                |
| `.claude/skills/playwright-component-testing/`, `.agents/…`                                                                  | `npx playwright init-skills`                                                                     | Component testing                                                                                                                                                           |

After creating a project from the template, search the `playwright-e2e` references for `<!-- YOUR PROJECT: ... -->` markers and fill in the details that are yours (application areas, test users, data strategy). Re-running `skills:sync` keeps those files — wico only rewrites what it generates.

## Project structure

```
playwright-ts-template/
├── src/
│   ├── pages/                 # Page objects (*.page.ts) — components/ for shared pieces
│   ├── tests/                 # Specs (*.spec.ts)
│   ├── helpers/               # Utilities
│   └── test-data/             # Static test data
├── .claude/skills/            # Claude Code skills (playwright-e2e + official Playwright skills)
├── .agents/skills/            # The same skills for Cursor, Codex and Copilot
├── .cursor/rules/             # Cursor pointer rule
├── .github/
│   ├── workflows/tests.yml    # lint · sharded tests · merged report
│   ├── instructions/          # Copilot pointer
│   └── copilot-instructions.md
├── playwright.config.ts
├── eslint.config.mjs · .prettierrc · tsconfig.json
├── Dockerfile · .dockerignore
├── Makefile
└── CHANGELOG.md
```

`tsconfig.json` declares the aliases `@pages/*`, `@tests/*`, `@helpers/*` and `@test-data/*`; Playwright resolves them.
